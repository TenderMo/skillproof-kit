# Guide structure

Start with what the reader can accomplish. Add requirements only when they affect the example.

For a command-line guide, show installation from a checked-out source tree, a complete command, a realistic input, and the expected output. Explain exit codes when the command is used in CI.

For an API guide, show the public entry point and a minimal caller. Keep internal implementation details in developer documentation.

For updates, verify each changed statement against the relevant code or an authoritative source. Record environment-specific verification limits with the affected example.
