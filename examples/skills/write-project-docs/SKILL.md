# Write project documentation

Read the implementation, CLI help, and existing examples relevant to the requested document. Describe observed behavior and keep proposed features in a roadmap.

Organize the document around the reader's task. Include prerequisites, the shortest useful example, expected output, and troubleshooting for known failures. Adapt the language and depth to the intended audience.

Use [references/example-structure.md](references/example-structure.md) when creating a new guide. Preserve an existing project's structure when updating one section.

Run documented commands in an isolated working directory when practical. Report which examples were verified. Check local links and explain any setup that requires an account or external service. Save the editable Markdown source.
